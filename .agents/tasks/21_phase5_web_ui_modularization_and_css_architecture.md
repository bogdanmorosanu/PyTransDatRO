## Technical Architecture & Design Decisions

### 1. Modular CSS Architecture (`webapp/src/style/`)
The monolithic `components.css` was split into 6 focused files, eliminating bloated styling rules:
- **`layout.css`**: Enforces the 480px workbench panel width invariant, sticky folder bookmark tabs bar, and modal overlay structure.
- **`forms.css`**: Centralizes text inputs, select dropdowns, the sliding direction toggle, and drag-and-drop dropzones.
- **`buttons.css`**: Standardizes button variants, including the theme-native anchor CTA (`.btn-primary`: `#f8fafc` on dark obsidian; `#0f172a` on light porcelain) and code-block copy buttons.
- **`badges.css`**: Enforces metric color isolation (`--color-metric-text: #38bdf8`) for the Quasigeoid height ($\zeta = h - H$), strictly isolating physical measurements from status colors (green/yellow/red).
- **`menus.css`**: Implements the user-requested menu item aesthetic for the header Help button and future application menus.
- **`telemetry.css`**: Encapsulates full-page usage analytics, SVG timeline graphs, and the 0.1° spatial matrix canvas viewport.

### 2. Reusable UI Factories (`webapp/src/ui/`)
- Avoided framework dependencies (React, Vue) while preserving declarative component generation in pure TypeScript.
- Every control supports full keyboard accessibility (`tabindex`, Arrow keys, Enter/Space activation, Escape dismissal) and semantic ARIA attributes (`role="radiogroup"`, `role="menu"`, `aria-checked`, `aria-expanded`).
- Automated testing in `ui.test.ts` validates DOM generation, event callbacks, keyboard navigation, and clipboard integration.
